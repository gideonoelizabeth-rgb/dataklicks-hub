Excel exercises (retail sales data)

Open retail_sales_2025.csv in Excel. The columns are: A Order ID, B Order Date, C Month, D Region, E Category, F Channel, G Units, H Unit Price (NGN), I Unit Cost (NGN). Do each exercise, then open the answer to check.

Excel 1. Work out revenue and profit for every order

In J1 type Revenue and in K1 type Profit. In J2 enter =G2*H2 and in K2 enter =G2*(H2-I2), then fill both down to row 3001. Add a total with =SUM(J2:J3001) and =SUM(K2:K3001).

Check: total revenue ₦308,018,200 and total profit ₦71,928,585 (a margin of 23.4%).
Excel 2. Revenue by region with SUMIFS

List the five regions in a small table and use =SUMIFS(J2:J3001, D2:D3001, "Lagos") for each, changing the region name.

Check: Lagos ₦120,215,200 · Abuja ₦64,650,400 · Port Harcourt ₦51,603,800 · Ibadan ₦38,690,300 · Kano ₦32,858,500.
Excel 3. Count online orders in Lagos with COUNTIFS

Use =COUNTIFS(F2:F3001, "Online", D2:D3001, "Lagos").

Check: 726 orders. Now change the region to find the others: Abuja 265, Port Harcourt 205, Ibadan 173, Kano 113.
Excel 4. Profit margin by category with a PivotTable

Select the data and choose Insert, then PivotTable. Put Category in Rows and Revenue and Profit in Values (Sum). Next to the pivot, add a margin column: profit divided by revenue, formatted as a percentage.

Check: Beauty 46.8% · Fashion 40.7% · Home & Kitchen 28.6% · Electronics 16.4% · Groceries 13.4%. Electronics earns the most revenue (₦174,272,200) but has the second-lowest margin. What would you recommend?
Excel 5. Chart the monthly trend

Build a second PivotTable with Month in Rows and Revenue in Values, then insert a line chart.

Check: revenue rises from ₦17,038,300 in January to ₦38,258,500 in December, with a dip in July and August and a jump in November.

SQL exercises (retail sales data)

Use any SQL tool that can import a CSV, for example the free DB Browser for SQLite. Import retail_sales_2025.csv as a table called sales and rename the columns to: order_id, order_date, month, region, category, channel, units, unit_price, unit_cost. Try each query yourself first.

SQL 1. How many orders are there? 
SELECT COUNT(*) AS orders
FROM sales;
Check: 3000.
SQL 2. What is the total revenue? 
SELECT SUM(units * unit_price) AS revenue
FROM sales;
Check: 308018200.
SQL 3. Revenue by region, biggest first 
SELECT region,
       SUM(units * unit_price) AS revenue
FROM sales
GROUP BY region
ORDER BY revenue DESC;
Check: Lagos 120215200, Abuja 64650400, Port Harcourt 51603800, Ibadan 38690300, Kano 32858500.
SQL 4. Profit margin by category 
SELECT category,
       ROUND(100.0 * SUM(units * (unit_price - unit_cost))
             / SUM(units * unit_price), 1) AS margin_pct
FROM sales
GROUP BY category
ORDER BY margin_pct DESC;
Check: Beauty 46.8, Fashion 40.7, Home & Kitchen 28.6, Electronics 16.4, Groceries 13.4.
SQL 5. Regions with more than 200 online orders (WHERE and HAVING) 
SELECT region, COUNT(*) AS online_orders
FROM sales
WHERE channel = 'Online'
GROUP BY region
HAVING COUNT(*) > 200
ORDER BY online_orders DESC;
Check: Lagos 726, Abuja 265, Port Harcourt 205. Ibadan (173) and Kano (113) are filtered out. WHERE filters rows before grouping; HAVING filters the groups afterwards.
SQL 6. Month-on-month revenue growth (window function) 
SELECT month,
       revenue,
       ROUND(100.0 * (revenue - LAG(revenue) OVER (ORDER BY month))
             / LAG(revenue) OVER (ORDER BY month), 1) AS growth_pct
FROM (
  SELECT month, SUM(units * unit_price) AS revenue
  FROM sales
  GROUP BY month
) AS m
ORDER BY month;
Check: January has no growth value. Then: Feb 25.0, Mar 0.3, Apr 2.9, May 6.0, Jun 12.4, Jul -4.1, Aug -4.0, Sep 7.5, Oct 8.7, Nov 24.4, Dec 9.0. LAG looks at the previous row, here the previous month.

Power BI practice: a loan portfolio dashboard

This is a small star schema: one table of loans (fact_loans) and three lookup tables for branches, products and dates.

  1. In Power BI Desktop choose Get data, then Text/CSV, and load fact_loans.csv, dim_branch.csv, dim_product.csv and dim_date.csv.
  2. In Model view create relationships: fact_loans[branch_id] to dim_branch[branch_id], fact_loans[product_id] to dim_product[product_id] and fact_loans[disbursed_date] to dim_date[date]. Mark dim_date as the date table.
  3. Create the measures from measures.dax (Total Disbursed, Outstanding Balance, Loan Count, PAR30 % and the others).
  4. Add cards for the totals and a bar chart of PAR30 % by branch.
Check your dashboard
Expected: Loan Count 4,200 · Total Disbursed ₦4,942,261,000 · Outstanding Balance ₦2,665,961,200 · PAR30 % 6.93%. By branch, PAR30 % is Ikorodu 10.77%, Surulere 8.06%, Abeokuta 7.82%, Yaba 7.71%, Ikeja 4.75% and Lekki 4.36%. PAR30 means the share of the outstanding balance that is more than 30 days late.

Cheat sheets

Excel functions to know

SUMIFSAdd values that meet conditions: =SUMIFS(J:J, D:D, "Lagos")
COUNTIFSCount rows that meet conditions: =COUNTIFS(F:F, "Online", D:D, "Lagos")
AVERAGEIFSAverage values that meet conditions.
IFChoose between two results: =IF(K2>0, "Profit", "Loss")
XLOOKUPFind a value in one column and return another: =XLOOKUP(A2, Sheet2!A:A, Sheet2!B:B, "Not found")
INDEX and MATCHAn older way to look values up that also works in earlier Excel versions.
TEXTFormat a value as text: =TEXT(B2, "mmm yyyy")
TRIMRemove extra spaces from text before you analyse it.
PivotTableInsert, then PivotTable: summarise thousands of rows by any column in seconds.

SQL commands to know

SELECT ... FROMChoose columns from a table.
WHEREKeep only the rows that match a condition.
GROUP BYSummarise rows by a column, with COUNT, SUM, AVG, MIN or MAX.
HAVINGFilter the groups after summarising.
ORDER BYSort the results. Add DESC for biggest first.
JOINCombine two tables on a shared column. INNER JOIN keeps matches only; LEFT JOIN keeps every row from the left table.
CASE WHENCreate a column with if-then logic.
Window functionsLAG, RANK and running totals with OVER (...) compare a row with others without collapsing rows.
